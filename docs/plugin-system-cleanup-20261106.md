# 插件系统清理记录

本记录针对当前 `cli` 源码的插件发现、安装、信任、SDK、交互和原生执行链。对外规则和接口以[插件开发指南](plugin-development.md)及[插件规范](plugin-spec.md)为准；此前审查记录保留当时的验收事实。

## 已处理

- 移除 SDK 3 清单、服务声明和管理列表的兼容分支。只接受当前 SDK 4；旧目录和业务数据不会被自动删除。旧插件升级后须重新安装、审核和准备运行时。
- 插件状态命名空间只接受清单中的准确身份，不再接受将下划线替换为连字符的旧别名。依赖旧别名的 SDK 4 插件必须同步修改。SDK 文件变化后必须重新准备原生运行时；有额外依赖的插件须继续使用经审核的离线依赖，不能自动替换为基础运行时。
- 安装菜单中用户亲自提交地址即允许本次连接该主机和端口；更新已有来源时的私网连接确认和插件信任不能由 `--yes` 代答。降级和普通授信共用明确确认。信任界面展示来源、分支和内容指纹，授信绑定显示的指纹，确认前后内容变化时拒绝或撤销信任。目录和工具的授权依然由框架处理。
- 清单中错误的权限数组、重复权限和不支持的权限直接拒绝。插件菜单元数据拒绝控制字符，展示插件提供的名称和图标时转义终端标记。
- 移除不再使用的旧 Git 与指纹提示文案；保留现有的事务凭据、状态恢复和归属检查，不能因为名称中出现 legacy 就删除实际数据或弱化恢复边界。
- 提供[可复制示例](examples/example-plugin/)及双语菜单、命令行测试，开发指南补充取消、默认值、分页、授权和发布前检查。示例的命令行入口另在 Windows AppContainer 中执行验收。

## 仍需持续评估

- 预加载涉及运行时校验、并发、锁与取消，代码量较大。是否简化应先以相同条件的冷启动、热启动和取消测试衡量收益，再证明变更不会越过内容验证、进程回收及授权边界；不能仅凭代码量删除。
- ASAR 目录读取是带宿主授权的专用 SDK 接口。迁出前须核实所有实际插件调用方，并设计同等隔离和读取边界，不能用无授权的直接宿主访问替代。
- SDK 菜单规范与示例测试不能自动证明所有外部插件都符合四字文案、图标占位和中英文要求；插件维护者需要对自己的动态界面及目标终端单独验收。
- 原生执行当前只支持 Windows；其他平台未实现，明确拒绝执行。测试通过不代表冻结发布包、其他机器或所有业务插件均已验收。
