# 发布签名与迁移

自更新默认拒绝没有签名的二进制。SHA256 只能证明内容一致，不能代替发布者认证。Ed25519 信任根需要发布负责人自行管理；本次整改没有生成或上传生产私钥，也没有修改外部 CI 设置。

发布仓库需要配置：

- Actions variable `OPSKIT_RELEASE_PUBLIC_KEY`：32 字节 Ed25519 原始公钥的 Base64。
- Actions secret `OPSKIT_RELEASE_SIGNING_KEY`：对应 Ed25519 PEM 私钥。

CI 构建前用 `scripts/pin_release_key.py` 写入公钥常量；签名阶段通过 `scripts/sign_release.py` 为每个资产生成 `.sig.json`。签名覆盖规范化 JSON 的 `build`、`filename`、`sha256`；发布时上传签名旁车。密钥缺失会使签名步骤失败。私钥不写入项目文件、日志、插件容器或镜像。

运维人员可在本地可信配置中设置 `update.signing_public_key`；只应通过独立可信渠道核对公钥。不能将网络下载中的公钥自动接受为信任根。轮换公钥需要先由旧信任根发布包含新根的受信版本，或由运维人员验证后人工迁移。当前实现仅支持单根，未实现自动轮换和 TUF 元数据过期策略。

下载签名检查和应用前重新检查防止 checksum 旁车及 pending 文件被修改。普通升级 build 必须大于已安装版本；崩溃恢复允许使用本地旧版本备份，这是恢复策略而非网络版本回退。备份目录和配置必须保持私有权限。

Windows 延迟替换脚本与宿主文件系统仍信任当前操作系统账户；插件不接触这些路径。宿主同账户的恶意进程可以改配置或二进制，不在插件沙箱的攻击者权限模型内。

初次安装脚本要求有效 SHA256 和 Ed25519 签名。为了不依赖尚未安装的 Python，使用 OpenSSL 3 的 pkeyutl 验证 `.signed` 和 `.sig` 旁车，校验签名中的资产名与下载摘要；公钥嵌入安装脚本。缺少工具、公钥或签名时拒绝安装，不静默降级。源码中的公钥留空，必须由发布负责人配置 CI 变量和 secret，再执行正式签名发布；本地合成密钥测试不能代替生产发布验收。
