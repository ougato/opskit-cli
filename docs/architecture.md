# OpsKit 架构

OpsKit CLI 提供软件、监控、网络及通用插件框架。官方模块由注册表装配；第三方插件通过清单、内容信任、不可变运行时和原生沙盒执行，宿主不导入第三方 Python 代码。

## 插件执行链

清单 SDK 版本检查 → 内容审核/信任 → 依赖准备及 SDK 摘要核验 → Windows AppContainer worker → 有限 RPC → 宿主 broker。SDK 3 与 RPC 传输版本独立。旧 SDK 1/2 必须升级并重新准备，不能继续调用已移除业务接口。

Windows 使用 AppContainer、Job Object、期限、进程树回收和工作区归属记录；Linux/macOS 后端尚未实现，明确拒绝。插件执行不使用 Docker/WSL，也不降级为普通宿主 Python。

## 宿主能力

SDK 提供目录读取、文件摘要、受限 HTTPS、上传、通用工具执行及产物凭据。每项能力由 broker 验证参数、插件身份、授权范围、期限和撤权。宿主工具使用独立参数数组，不经 shell，按用户权限运行；工具可能执行工程脚本，该边界须展示给授权人。

执行与产物操作共享资源锁。工具原始退出码由插件解释；宿主新建独立输出、核验身份与内容，按插件登记凭据。未知、变化、跨插件、活动目录均不能通过凭据清理。

## 状态与维护

插件管理包含安装、更新、卸载、权限与维护。维护包含更新回滚、沙盒清理、临时清理、缓存清理和空间设置。清理须依赖归属记录和摘要，不能扫描后直接删除未知目录。

最低剩余空间默认 2048MiB，可配置 256..1048576MiB；这是预检查和运行中检查，不是磁盘硬配额。旧业务配置字段仍保存，但读取通用阈值不依赖它们是否合法。

## 业务边界

特定编辑器配置、参数、成功码、平台产物规则、构建历史交互和保留策略属于独立业务插件。Cocos 源码位于独立 `plugin/cocos` 项目，内部仅使用公开 SDK。框架不加载该插件业务代码，也不自动安装或授信。

接口细节见 [插件规范](plugin-spec.md)，升级及旧数据保护见 [业务分离与迁移](sdk3-business-separation.md)。
