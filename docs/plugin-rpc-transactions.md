# 插件 RPC 提交边界与优化门槛

## 当前实现与已确认失败

每次 `core/plugin_sandbox.py::invoke` 独立执行状态事务。嵌套服务继承外层期限和授权依赖，但并不继承一个覆盖所有参与者的状态原子提交。提供方成功返回前已清理自身资源并发布其调用方分区；外层调用方仍须清理自身资源、复核期限和授权后，才能发布自身状态。

593快照1bef的真实已安装Linux验收中，首个授权计数调用的提供方计数已发布为1，外层在清理后检查期限时失败，外层结果文件不存在。证据在 `cache/plugin-install-receipt-20261016-r1/native-failure-r1`。这与当前独立事务实现一致，但暴露了调用结果与副作用不确定性的产品风险，不能标成整条链路安全验收通过。

不允许把超时、取消、连接中断或调用方状态未发布解释为“提供方没有执行”。平台当前没有自动重试、幂等请求键、持久调用回执或跨插件回滚保证。管理员也不应在原计数现场反复运行以获取绿色结果；查询与恢复必须保留现场。

## 已测开销与安全约束

在新Linux原生目录只执行首次授权调用的诊断中，外层22.73秒，嵌套服务描述6.99秒、业务调用8.26秒，原策略仍为30秒；新目录两份状态均发布。诊断包含cProfile开销，嵌套采集与重叠累计时间不能相加；不是性能基准，也不能归因原失败。原始 `outcome.json`、`profile.txt`、`caller.prof` 保存在同一批cache根。

描述和调用都运行实际提供方，并各自准备状态、清理和提交。描述核验实际 `service_api_version` 和清单合同；业务调用也执行worker合同核验。优化不得仅缓存清单版本而跳过实际业务版本检查，不得移除撤权复核、结束后清理确认、身份/目录锁、资源账本或提交前期限检查。

## 后续实施顺序与验收

2026-10-16补充分阶段诊断：实际安装595候选wheel的269运行文件先逐字节核对，在新Linux原生目录执行一次授权计数并主动停止，未重试旧现场。外层17.49秒，描述5.49秒、业务调用5.64秒，三个`_save_state`分别约1.00/0.94/0.99秒；没有cProfile嵌套启停，采用宿主monotonic父子span。完整树形时间轴在`cache/plugin-content-receipt-20261016-r1/rpc-stage-trace-r1.json`。本轮两份状态均提交，但不是完整RPC验收、代表性基准或原超时原因证明。描述中的初始化当前会提交，直接跳过提交可能改变插件行为；这一秒开销也不能解释全部调用耗时，因此没有借此更改语义或删除安全阶段。

1. 对固定工作量测量worker启动、快照、资源分配、描述、调用、清理和状态发布，记录父子时间轴、并发负载、p50/p95/RSS；独立计时器不得在嵌套退出时停掉外层采集。保留原失败，不用新目录成功覆盖。
2. 审查worker会话复用或同一次沙箱内的描述与调用协商。必须保持调用前实际合同核验，不能把不可信服务对象带回宿主；需验证状态可见性、描述中的初始化、撤权及版本不匹配行为，明确API兼容性后实施。
3. 写服务需要持久幂等协议。键由宿主绑定调用者/提供方内容身份、服务、方法和参数摘要；同键不同参数拒绝，同键并发串行，已提交结果可查询。插件任意外部网络副作用不能由平台本地回执承诺恰好一次，应由业务端参与幂等。
4. 本地状态与回执须在同一可恢复提交中绑定；先写回执再写状态、或反过来，都存在崩溃窗口。损坏/缺失回执必须返回不确定，不能默认未执行后重试。需定义配额、保留期、授权撤销后的查询权限及过期键处理。
5. 明确采用独立事务加幂等回执，还是跨插件协调提交；跨插件协调还需统一锁顺序、隔离未提交状态、根会话日志、全部参与者恢复及外部副作用边界。当前没有实现其中任一新保证。

必须验收的失败点包括：提供方提交前后、响应发送前后、调用方接收后和提交前后；超时、取消、父进程被杀、daemon失联、磁盘满、回执损坏、并发相同键/不同摘要、权限撤销及服务升级。通过标准是结果可判定或明确不确定、无盲目重试、无跨调用者状态/结果泄漏、配额有界；不能只检查一次正常计数。

## 实施决策：独立事务与持久回执

后续采用独立提供方事务与显式幂等请求，不将任意插件组合升级为分布式原子事务。原因是平台现有锁、恢复日志与状态分区以单个提供方/调用方为单位，而且插件可能已发送外部网络请求；回滚本地目录不能撤销外部业务。调用方失败以后，已成功的提供方事务继续有效，调用方通过同一个请求键查询结果，而不是重新执行业务。此节是实施规格，当前599候选尚未实现这些新能力。

请求键需要由插件业务持久保存并在恢复时复用。仅以一次进程内序号或随机宿主调用ID作为键，不能解决调用方重启后不知道原请求身份的问题。SDK增加显式请求/查询接口，普通业务参数不能隐式充当宿主控制参数；清单需要能表达方法的幂等协议版本。旧接口的合同、描述初始化与提交语义继续保留，不能通过删除描述提交或自动生成不可恢复的临时键宣称旧调用已具备幂等。

宿主绑定以下字段后计算请求身份，插件不能指定另一个调用者或提供方目录：

| 字段 | 权威来源与约束 |
|---|---|
| 调用者、调用者内容摘要 | 实际外层invoke会话及当前授权复核 |
| 提供方、提供方内容摘要 | 唯一发现结果、快照与当前授权复核 |
| 服务、方法、业务API版本 | 已授权清单合同，实际worker仍复核版本与可调用方法 |
| 业务请求键 | 调用者显式提供的有界字符串，跨重试保持一致；不直接用于路径 |
| 参数摘要 | 有限JSON验证后采用固定格式规范化，包含args/kwargs及格式版本 |
| 协议代次 | 持久格式明确版本化；不能因清理或升级让已消费的键重新变成新请求 |

相同业务键的参数变化必须拒绝，不能因为把参数摘要也放进最终路径而误认为是另一条新请求。请求键索引与参数摘要分开存储并比较；对象键排序不改变业务语义，数组顺序保留，bool/int及非有限数规则沿用plugin_json。没有定义的数字规范化不能交给默认JSON行为猜测。

## 调用状态机与崩溃判定

准入、状态恢复、授权、合同核验及额度检查在实际提供方调用锁下完成。请求意图必须在允许业务worker执行之前持久化并确认；普通JSON原子替换不足以证明断电持久性，需要同时确认文件和父目录同步或明确拒绝不支持的文件系统。意图记录的字段、大小、根身份与损坏处理也必须经过监督，不能在主线程新增无界读写。

| 持久事实 | 允许操作 | 返回与恢复规则 |
|---|---|---|
| 无意图、无回执，目录/日志完整且代次有效 | 持锁创建并确认意图，随后才允许启动业务worker | 意图未确认前不得执行业务 |
| 意图存在、无可验证提交回执 | 保留现场并提供查询；不得再次启动同键业务 | 返回明确不确定，不能默认“未执行” |
| 状态事务处于候选/切换中 | 先执行现有归属恢复并重新核对状态与回执绑定 | 恢复不能确定时保留，禁止重试 |
| 状态及同一次提交中的回执完整、绑定匹配 | 当前授权复核后返回原结果；不启动业务worker | 返回已提交结果，即使上次响应丢失 |
| 意图、回执、代次或根身份损坏/不匹配 | 保留并拒绝执行/结果披露 | 返回不确定或授权拒绝，不修造新事实 |

一旦意图已持久确认，即使进程实际上尚未进入业务，也可能因崩溃留下不确定状态。首版选择保留并停止自动执行，而不通过PID已退出、缺少结果文件、超时或租约释放推定业务没有执行。需要人工或业务端对账的请求不得被平台自动清理后重试。

提供方返回候选状态后，宿主把结果回执注入同一个受管候选目录；状态与回执一起由现有发布事务切换。不能分别写两个最终路径，也不能在状态提交完成后补写“成功”回执。回执记录完整绑定、参数摘要、结果有限JSON及格式版本；超出结果/存储额度时应在执行前拒绝可预知的需求，执行后仍超限则保留意图并返回不确定，不能返回“未执行”。

宿主回执目录不得进入guest的seed，不允许guest返回同名路径或修改旧回执。新候选必须从可信已提交状态保留既有回执，再加入当前结果；需要同步改造状态复制、归档校验、候选准备、库存及配额，并测试guest伪造/覆盖回执拒绝。仅在tar中加入一个普通结果文件是不合格实现。

意图保留至回执已提交并经恢复复核；如清除意图，回执及代次记录仍必须阻止旧键再次执行。首版不做按TTL自动删除已消费的键。明确容量与保留期后再引入代次关闭和管理员归档，已关闭代次拒绝执行，不能因回执不见而重新接受旧键。额度须覆盖意图、回执、结果、暂存、备份和不确定对象，不能只限制单个文件大小。

## 实施批次与验收依赖

1. 固定版本化绑定/编码及键冲突语义，添加确定的规范化向量；仅实现后同步接入调用者，避免留下无人使用的协议模块。
2. 在监督worker中接入受管根身份、意图独占创建、持久确认及有界查询；真实双进程同键只能一次获准，持锁冲突不能等待超过外层期限。
3. 扩展候选准备与提交，隔离宿主回执，保留旧回执并计账；分别在两次rename前后杀死宿主/worker，状态与回执恢复结果一致。
4. SDK/清单/文档同时版本化，提供请求与查询，不把超时自动转为重试；描述初始化的兼容策略单独验收。服务升级、调用者升级或撤权后不得向旧主体泄漏结果，也不得自动把旧键迁移成新身份调用。
5. 在真实已安装容器和冻结CLI中执行响应丢失、调用者提交前失败、相同键并发、参数冲突、损坏、磁盘满、额度耗尽、取消与撤权矩阵；明确外部业务幂等仍由服务端参与。

完成标准是已提交结果可查询，不能判定的请求明确保留为不确定且不再次执行。新增单元测试、一次正常计数、599候选完整RPC通过或候选目录原子切换，都不能单独关闭本节门槛。
