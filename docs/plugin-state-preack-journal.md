# 状态候选确认前的归属日志

2026-10-15：候选准备现在复用现有 schema1 状态事务日志，不增加第二份日志或自动猜测目录归属。

准备 worker 在 staging→transaction 锁内检查配额、创建 wrapper 和空 new 目录，记录平台绑定的 plugin/caller 与目录身份，并写入、fsync 事务记录，然后才发送 allocated 响应。父进程确认后才允许解码及提取候选内容；提取前后再次检查目录身份。插件不能通过报文指定状态所有者。

发布阶段持原有实时授权锁，确认已有 pending/uncommitted 记录、目录拓扑和身份，重新 fsync 并核对日志路径仍指向同一文件，再执行原有改名事务。不会另建一份发布日志。取消时先确认 worker 退出，仅对匹配显式所有者及目录身份的未提交事务执行现有中止恢复；身份不明、已提交或损坏记录继续保留。

这覆盖了有效归属日志创建后、父进程收到分配确认前的进程崩溃窗口。创建日志之前的 mkdir/身份读取崩溃，以及日志部分写入仍可能留下未知空目录或损坏记录，不能按名称自动删除。文件 fsync 不代表目录和全部候选数据具备断电持久性；同 UID 恶意宿主竞争、故障网络文件系统硬期限和全局物理配额仍未验收。
