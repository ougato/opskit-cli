# 插件授权读取监督设计

复核日期：2026-10-15。内容/指纹、实时授权、启动timeout、WSL distribution、private_targets、SDK/网关catalog、完整manifest及插件发现/服务目录已接入受监督读取。状态发布I/O仍未全部覆盖。实现属于独立平台工作树，不修改第三方插件。验收终态与历史失败统一见[实施验收台账](implementation-acceptance.md)，本页只维护当前设计。

## 所有权、期限与传输

每次外层调用拥有一个惰性ContentInspector，复用network.worker的owned_process、Windows Job/父死亡保护和wait_result。嵌套调用共享reader与剩余期限，不能关闭外层reader。退出、读取错误、超时或取消均回收进程；已关闭的reader不能复用。

POSIX客户端清理遇到killpg权限错误时，只在poll确认并回收本平台启动的已退出leader后重试同一group；活leader或第二次权限错误仍明确失败，不能吞掉真实清理失败。macOS已复现只剩未回收leader的group返回EPERM，回收后返回不存在；真实后代存活场景另行验证，不能仅凭leader退出宣称整个group已清理。

执行快照仅把平台刚创建的TemporaryDirectory路径规范化，兼容macOS系统管理的/var别名；第三方源码/清单的链接拒绝不变。默认macOS临时目录与人为创建的临时目录别名均有实际reader/client回归；设置测试TMPDIR不能替代生产路径修复。

请求使用256KiB固定共享内存邮箱，提交不依赖可能阻塞的管道写入；普通响应及分块控制帧仍受64KiB通道约束。完整manifest响应复用同一邮箱，详见下节。不使用pickle传输不可信对象，不返回整份配置或任意异常路径。请求字段、文本长度、响应精确形状及类型均验证。读取进程只运行平台读取器，不导入第三方业务，不写状态，不缓存许可。

_execution_budget在启动配置读取前记录开始时间并建立所有权。timeout查询有30秒启动上限；读取后的实际deadline取原开始时间加配置timeout与父deadline的较小值，不能从读取完成时重新计时。读取已耗尽较短业务期限时，在业务执行前拒绝。所有权finally覆盖contextmanager yield之前的启动读取失败。

每次操作在开始前和返回后核对同一剩余期限。内容与授权读取单次最多300秒，配置、catalog和manifest查询单次最多30秒；均不得超过父剩余预算。check_authorization和_check_live_authorizations没有同步读取回退，独立调用建立自己的完整预算作用域，退出后恢复原scope/deadline并回收reader。

## 完整执行清单

_invoke在初始校验和复制快照后调用_read_manifest；同一reader重新读取每份清单，不只返回摘要。原YAML普通文件、1MiB输入、深度/事件/链接约束不变。读取与纯解析分离为load_manifest和_parse_manifest，父进程复用同一规范化谓词核对全部字段，root仅由宿主请求绑定，响应不能声明其他根目录。

响应先发送精确ok/size信封，总量最多8MiB，再以256KiB邮箱传输JSON块。每块offset/size必须为精确整数并符合剩余长度；父进程复制后仅确认非最后一块。最后一块不确认，避免确认事件吞掉下一次请求。所有帧、解析和返回复核共享同一期限，失败或取消关闭reader；不为每一块重新计时。普通配置/摘要查询可以继续复用该reader。

清单包含entry、展示信息、权限、uses和service_contracts全部字段。父进程再次规范化并比较完整JSON表示，拒绝额外字段、root注入及布尔值冒充整数。执行仍比较复制前后完整清单和实际内容身份；读取监督不能替代信任或服务授权。

## 插件发现与服务选择

list_manifests与服务发现通过_read_inventory使用同一个reader及剩余期限，单次最多30秒。读取器先扫描整个目录，保持4096条目/256清单上限，再解析并按all/name/service选择；不能通过窄选择绕过扫描额度。重复插件身份仍返回，由服务解析拒绝歧义，不采用最后一个覆盖前一个。

结果先传精确数量，再逐条传directory及完整manifest；每条沿用8MiB分块边界，整个库存允许超过8MiB但最多256条。非最后条目收到确认后才发送下一条，最后条目不确认；块间与条目间确认共用同一期限。父进程核对数量、目录名唯一性和路径约束、规范化清单及选择条件，root只能由宿主目录重建。中途失败关闭reader，不返回部分清单。

authorize_service、提供方发现、服务调用、访问解析及描述/查询均建立或复用执行预算，reader不执行业务函数。服务访问解析使用受监督的新鲜身份与授权边复核，移除宿主同步信任读取。交互式菜单不把等待用户输入计入整段执行期限。安装包、双平台专项/完整回归及本批真实Docker RPC均已有终态证据；不覆盖完整状态机或daemon故障恢复。

## 授权、锁与撤销

宿主绑定调用链中的身份、指纹、服务边和已使用私网列表，请求不能采用插件自称的身份。每次复核重新读取实际配置与信任文件，复用现有启用、is_trusted及is_service_authorized谓词。显式宿主路径保证开发/打包/子进程使用同一存储。

状态提交由父进程按configuration→trust顺序持锁。锁内请求新复核、等待结果、检查剩余期限，再发布状态；reader不申请这些写锁。锁外检查结果不能作为最终提交许可。平台修改接口与提交互斥，不代表绕过锁直接改文件的外部进程也受同样保护。

private_targets仅在真正创建出口前查询当前插件的列表；无network权限不查询。每份最多256项、单值512字符、UTF-8 JSON总量16KiB。坏结构或超量固定拒绝，不用空列表冒充有效授权。已使用列表持续保留到最终状态提交，嵌套调用保留外层依赖；最多256份快照、合计64KiB。实时复核要求原列表仍为当前列表子集，新增或重排不扩展现有代理，删除则拒绝调用。当前为每秒轮询检测与最终提交复核，不是即时逐请求撤权。

WSL distribution仅在无原生Docker且Windows具备WSL时查询，最多128字符并遵循名称规则。enabled查询保留原真值语义，并在内容读取前拒绝禁用。以上窄查询在各自消费时点重新读取，不共享一份长期配置快照。

## SDK与网关目录

core/plugin_catalog.py负责目录身份读取，ContentInspector区分catalog/gateway_catalog操作。SDK目录限制普通文件、链接数、16KiB、打开前后身份及读取长度/mtime一致性；检查当前SDK库存摘要，仅返回schema/base/image/lock/code/fingerprint六字段。父进程再次验证响应字段，再核对插件指纹与Docker image标签。

网关目录沿用有界YAML的普通文件/父路径链接拒绝与结构预算，要求精确四字段、正式POLICY和固定base；读取进程计算实际网关源码摘要。父进程核对固定响应及真实image标签，不在宿主同步读取源码。网关与SDK不共享依赖库存或授权记录。

作用域内复用原reader与剩余预算；独立SDK/网关image入口拥有完整预算作用域。每次重新读取，不缓存目录许可；损坏、SDK/网关摘要变化、超时或取消均不能继续Docker执行。新增RuntimeCatalogError只区分目录不可用与期限失败，网关不能把期限失败转换为有效目录或SDK回退。

上述运行接入后续已取得终态：同一运行代码三端完整回归、Windows/macOS当前wheel安装恢复/94help与103入口、Linux当前SDK真实RPC及正式网关均通过。实际Linux信号探针在插件/客体后代就绪后对拥有CLI发SIGINT返回130并自行清理；SIGTERM返回-15后显式恢复1条遗留记录，二者worker均移除且旧状态摘要不变。证据及准确跳过数见implementation-acceptance最新终态。其余监督I/O、未记录暂存归属/容量、完整发布崩溃与断电、残缺记录人工修复、live CONNECT实际信号及daemon/其他平台矩阵继续开放；不将SIGTERM后的显式reconcile描述为自动清理。

状态发布的下一批必须先解决恢复再扩展I/O监督。一次性目录崩溃探针已确认：_publish_state把root改名为.previous后若进程退出，root缺失但旧备份完整；当前_copy_tree把缺失root当作首次运行，生成空seed。此证据只说明错误重启路径，不代表旧备份已被删除。修复需在持有插件状态锁、准备seed之前检查事务；无法证明归属/阶段的旧.previous必须明确拒绝运行并保留，不能当作无状态继续，也不能仅凭名称删除。

当前已增加_require_resolved_state：self/caller分区准备完成后、网络/容器资源创建前拒绝任何.previous条目，包含悬空链接；状态解码前及发布前再次检查。真实子进程在首次改名后退出的回归证明旧备份和候选数据保留，未完成事务不能进入空seed执行。这是失败时拒绝继续的边界修复，尚不提供自动恢复、事务归属记录、断电持久化或状态I/O监督；下述恢复门槛继续保留。

新事务需要绑定平台生成的事务身份、插件及认证调用方分区，记录旧状态是否存在、staging与备份身份及发布阶段。恢复动作只能作用于有界、无链接且身份匹配的拥有目录。发布后的清理失败与发布前失败必须区分，不能把已经提交的状态当作可回滚的普通失败。准备、旧状态改名、新状态发布、持久化和清理之间都需真实子进程退出测试；持有状态锁时完成恢复，不能由并发恢复者覆盖活动调用。数据与目录持久化及跨平台语义需要实际验证，单纯原子改名不等于断电安全。

验收应同时覆盖首次提交和已有状态、self与caller分区、阶段记录缺失/损坏/外部替换、路径或链接注入、恢复重复执行、磁盘满与权限失败；旧数据、候选数据及恢复证据不能因取消或超时被误删。I/O监督必须保持父进程授权提交锁和新鲜复核，子进程不能脱离父监督继续发布。该方案尚未实现，不能以当前清单读取专项关闭此门槛。

实现分三批推进，不能用单一“恢复成功”测试合并关闭：

1. 独立宿主事务模块：定义有界精确结构、平台生成身份、目标/插件/调用方绑定、父目录及旧新目录身份；无链接打开、创建独占与写入失败保留策略。先覆盖坏记录、替换、错分区和旧.previous无记录拒绝，不改运行路径。
2. 接入现有插件状态锁和发布调用：准备候选权限后创建记录；每次改名与记录更新均有崩溃探针；恢复依据身份匹配的实际拓扑，不仅依赖可能落后的阶段字段。记录最后退役；部分清理、首次提交及恢复过程中再次退出都必须幂等。清理错误与提交错误单独表达，保留configuration→trust锁内新鲜授权复核。
3. 完成持久化与监督验收：对实际支持文件系统验证flush/fsync或平台等价能力；验证磁盘满、权限、取消及父进程死亡；完成Windows/Linux/macOS专项后再构建固定快照、wheel与安装入口验证。尚无实测的断电保证不得写入产品承诺。
