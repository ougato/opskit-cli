# 插件系统审查与验收记录（2026-11-06）

> 以下是当时的验收记录；后续已移除 SDK 3 管理兼容，当前规则以[插件开发指南](plugin-development.md)为准。

本次审查覆盖插件发现、SDK、服务契约、菜单交互、授权、隔离执行、安装更新、Cocos 构建以及发布包。开发者使用方式见[插件开发指南](plugin-development.md)，SDK 3 迁移见[升级指南](plugin-native-upgrade-guide.md)。

## 已处理的问题

- SDK 4 删除无法在隔离进程中兑现的工具接口，统一公开菜单签名、取消语义和服务契约。SDK 3 插件仍可在管理列表中查看、更新或卸载，但须升级、重新审核和准备运行时才能执行。
- 删除宿主侧未使用的服务代理缓存、空操作式卸载逻辑和隐式引导安装；插件间服务继续通过声明的契约和宿主授权调用。目录、工具等授权由框架展示和管理，插件不自行决定授权选项。
- 连续编号的长菜单自动分页，Cocos 的工具、历史和清理列表使用分页；取消不会被当作默认选择。开发指南列明四字固定操作名、主题图标、中英文文案和交互接口。
- Cocos 构建设置保留已有值，重置为明确操作；旧命令和旧版可移植配置给出迁移提示，避免默默按新语义构建。插件帮助及缺失插件的错误提示已修正。
- 修正打包依赖与过期隐藏导入。原生调用去掉一轮重复的运行时扫描；准备运行时来源和实际执行副本仍分别做内容校验，不通过时拒绝执行。

## 验收范围

- 插件相关框架测试第一轮结果为 1,613 项通过、34 项跳过、8 项失败；失败涉及旧测试夹具和插件不存在时的错误提示，修正后这 8 项单独复测通过。插件安装与更新的独立回归为 43 项通过。
- Cocos 插件测试为 105 项通过。原生运行时、快照校验和真实沙盒调用的专项测试为 22 项通过。源码的中英文调用在真实 AppContainer 中验证隔离和状态提交；Windows 可执行包还验证了失败回滚和撤销授权。
- 使用源码宿主时，Creator 3.8.7 在独立客户端克隆中成功构建 `web-mobile`，版本从 1.0.3 更新为 1.0.4；保存的构建配置在另一个独立克隆路径成功重放，产物中的版本与提交身份一致。版本提交仅发生在测试克隆中，没有推送。
- Windows 可执行包通过 30 项命令检查；独立安装包通过 109 个帮助入口和 123 项命令检查。冻结包本身的真实 Creator 构建未单独验收，构建工具的结果与隔离机制是分开验收的，不能把其中一项通过推断为所有平台或整机环境均已覆盖。

## 保留限制与后续工作

- 每次执行仍会复制并验证隔离运行时；大型 Python 运行时和慢磁盘可能导致启动较慢。本机对同一测试插件命令交替运行两次，优化前为 13.61、12.47 秒，优化后为 13.01、12.43 秒；样本太少，不能据此断言整体有明显提速。单次性能采样中运行时快照和受监控进程启动、等待均占有明显时间，继续优化时须同时证明来源、快照及竞争修改的安全边界，不能单纯跳过校验。
- 原生插件沙盒当前仅支持 Windows；Linux 和 macOS 后端未实现，不会退回无隔离执行。
- Cocos 列出 Creator 平台并检查安装情况；目前只有网页平台具备构建产物验证，真实构建本次只验证了 `web-mobile`。其他平台须完成各自的工具链、产物校验和实机验收后才能启用。
- 可移植配置已在两个不同工作区路径验证，并未在另一台物理机器上验证；目标环境仍需匹配版本的 Creator、Git、项目及框架授权。
- 独立安装包构建时，Setuptools 提示 `pyproject.toml` 中的许可证表和许可证分类写法已弃用，需在其提示的 2027-02-18 前升级构建元数据并验证最低构建依赖版本。
- 本次未对用户实际客户端执行破坏性分支同步或构建。测试启动的 Creator 自行更新了本机共享的构建界面缓存；首次冻结包测试触发过 PyInstaller 默认可重建缓存的清理，后续构建已使用隔离缓存。
