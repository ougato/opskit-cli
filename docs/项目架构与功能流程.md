# OpsKit 项目架构与功能流程

本文按当前源码梳理从启动到菜单和命令的主要流程，供框架维护者定位问题，也帮助插件开发者辨认框架和业务的边界。文中描述的是**现有实现**；可直接调用的插件接口以[插件开发指南](plugin-development.md)和[插件规范](plugin-spec.md)为准，不能因本文提到内部函数就直接从插件导入。

启动入口到首屏的逐文件审查、规范差距和重构待办见[启动至首屏审查与待办](启动至首屏审查与待办.md)。

源码可能继续变化。菜单、命令、权限或生命周期改变时，应同步检查本文、对应权威契约与测试。历史设计和已经废弃的接口不作为当前实现；[2026 年 10 月验收记录](validation-status-20261015.md)仅说明当时的范围，当前状态需以对应版本的验证证据为准。

## 总体路径与职责

```text
main.py
  ├─ 全局参数 / 帮助 / 版本
  ├─ 无子命令：启动初始化 → 注册官方模块 → 主菜单
  │     ├─ 软件管理 → 搜索 / 已安装 / 分类 → 软件操作
  │     ├─ 系统监控 → 概览 / CPU / 内存 / 磁盘 / 网络 / 进程
  │     ├─ 网络工具 → Ping / 路由 / DNS / 端口 / 测速 / IP
  │     ├─ 插件工具 → 插件管理 / 已安装插件入口
  │     └─ 偏好设置 → 主题 / 语言
  └─ 具名命令：对应命令组 → 菜单或脚本化业务入口
```

| 层次 | 负责什么 | 源码入口 |
| --- | --- | --- |
| 进程入口 | 控制台编码、源码环境自举、命令解析、根菜单及启动顺序 | `main.py` |
| 框架公共层 | 配置、主题、多语言、交互、平台检测、进程、更新、日志及插件隔离 | `core/` |
| 官方模块 | 软件、监控、网络、插件管理；由框架注册表装配 | `core/builtins.py`、`core/loader.py` 和各模块 `__init__.py` |
| 外部插件 | 清单定义入口，在隔离 worker 中运行，通过公开 SDK 请求宿主能力 | `core/plugin.py`、`core/plugin_sandbox.py`、`core/sdk.py` |

官方模块是宿主代码，可以使用框架内部模块；外部插件只能使用公开 `core.sdk`。外部插件不加入主菜单注册表，而是在“插件工具”中发现和分组。Cocos 是独立仓库中的外部业务插件，其项目、Git 和构建逻辑不属于框架 API。

## 启动、命令行与主菜单

### 启动顺序

1. `main.py` 设置控制台编码。源码模式按平台处理虚拟环境自举，Windows 还配置子进程启动；打包模式跳过源码自举。Typer 帮助在解析前加载语言，根级参数配置输出、非交互和普通确认行为。
2. 指定 `--version` 时输出版本并退出。没有子命令时要求可交互，调用 `_boot()`：确保配置、初始化日志和清理、主题与语言、平台预检，然后检查待应用更新。重要预检问题会显示并暂停；普通非 root 提示只记录日志。更新检查异常在此处被捕获，不能仅凭进入主菜单断言更新成功。
3. `_main_menu()` 通过 `core/loader.py` 发现模块。源码模式使用 `core/builtins.py` 的显式官方列表；打包模式优先使用静态注册表。模块加载失败会记录脱敏诊断并在菜单中提示，其他可用模块继续显示；按平台、模块启用状态和配置筛选，再按 `order` 排序。当前顺序为软件、监控、网络、插件；偏好设置由主菜单追加。
4. 主菜单首屏完成后才启动镜像检测、版本缓存刷新、自更新、遥测和更新健康确认；插件发现也在菜单就绪后启动。后台异常多数被捕获，因此出现缓存未刷新或更新未生效时要单独检查对应任务与日志，不能把首屏可用等同于后台任务成功。
5. 返回或取消时，主菜单回收待处理的插件预加载并执行退出更新检查。进入模块后返回回到主菜单；模块异常会显示错误并暂停，取消则回到上一级。

### 命令行分支

`main.py` 注册 `software`、`monitor`、`network`、`plugin` 命令组，其他偏好和业务命令由相应注册器接入。根回调对具名命令先初始化语言和主题；**不能据此推断所有命令都只读或都不执行 `_boot()`**：例如部分软件文本查询和无名称的交互入口会显式调用 `_boot()`，而已迁移的指定名称脚本化操作走独立路径。

全局 `--output text|json`、`--non-interactive` 和 `--yes` 的适用范围以[官方 CLI 契约](cli-contract.md)为准；并非所有命令都已迁移统一输出。`--yes` 不能代替插件信任、宿主能力授权或必要的业务参数。插件命令 `plugin run NAME -- ARGS` 将后续参数交给插件，不把插件业务参数解释为框架参数。

定位入口：`main.py` 的 `_app_callback`、`_boot`、`_main_menu` 和命令注册；启动初始化及菜单编排分别实现在 `core/startup.py` 和 `core/main_menu.py`，具体命令参见 `software/direct_cli.py`、`software/lifecycle_cli.py`、`monitor/cli.py`、`network/cli.py`、`plugin/lifecycle_cli.py` 和 `plugin/capability_cli.py`。

## 软件管理

### 菜单与选择

`software/menu.py:entry` 在进入时按当前平台预热安装状态缓存，提供搜索、已安装、开发工具、运维工具和系统工具。搜索匹配软件 key 和当前语言显示名；搜索、分类只展示当前平台支持且未隐藏的 recipe。结果按页展示，选择后进入统一操作页；有子菜单的 recipe 先列业务子项，例如 WireGuard 的服务端和客户端。

软件能力来自 `software/registry.py`、`software/base.py` 和 `software/recipes/` 下各 recipe，不同软件、系统和版本可有不同的安装方式及附加操作。显示状态来自检测及缓存，不是对每次操作成功的保证。状态错误时应检查当前平台、recipe 的检测与缓存刷新，而不是仅看菜单文字。

当前 recipe 的分类和平台声明如下；平台声明只决定入口支持范围，不等于该平台已完成真实安装验收。每项实现从 `software/recipes/<名称>/recipe.py` 进入，再按目标系统进入同目录的平台实现；WireGuard 的 `wg_server` 和 `wg_client` 共用 `wireguard` 目录。

| 分类 | 软件 / 子功能 | 声明平台 |
| --- | --- | --- |
| 开发工具 | Go、Java、Node.js、Python | Linux、macOS、Windows |
| 运维工具 | MySQL、Redis、PostgreSQL、MongoDB | Linux、macOS、Windows |
| 运维工具 | ClickHouse、Tailscale | Linux、macOS |
| 运维工具 | Docker、Nginx、RustDesk、x-ui | Linux |
| 运维工具 | WireGuard → 服务端、客户端 | Linux；服务端与客户端是父项下的隐藏子 recipe |
| 系统工具 | Oh My Zsh | Linux、macOS |

每个软件的检测、版本源、安装位置、服务操作和卸载效果应沿对应 recipe 跟踪，不能用其他软件的结果代替。具体可执行操作由 `has_upgrade`、`has_switch`、`has_diagnose`、`has_manage` 等能力决定；可用列表和脚本支持还可通过 `software list`、`software capabilities NAME` 查询。

### 操作流程

| 操作 | 主要步骤和结果 | 常见失败或取消位置 |
| --- | --- | --- |
| 安装 | 解析依赖；根据 recipe 走专用向导、版本选择器或普通版本选择；适用时检查已有版本、磁盘空间和确认；`software/actions.py` 执行并报告结果。 | 依赖失败、无可用版本、空间不足、拒绝重装/确认、下载安装失败或中断。磁盘检查使用配方声明的目标路径；未知目标或无法读取时提示未知，不能作为空间充足的证明。专用向导和版本选择器的确认时机不同，不能假定所有 recipe 都有同一确认步骤。 |
| 卸载 | 检测已安装项；多版本软件可选择版本或全部，确认后执行；单版本走对应卸载。 | 未安装、用户返回或拒绝、目标版本不存在、系统权限或卸载命令失败。具体数据是否删除由 recipe 决定，应检查实际提示和实现。 |
| 升级 | 解析依赖、检测当前版本、获取并筛选较新版本；目标已安装时可切换，否则调用升级执行。 | 检测不到安装、版本源不可用、没有更高版本、选择取消或执行失败。 |
| 切换版本 | 仅支持相应 recipe，列出框架管理的已安装版本，选择后切换；当前版本不重复切换。 | 无已管理版本、选择取消、切换失败。 |
| 诊断 / 管理 | 根据 recipe 能力显示；进入具体软件的诊断或交互式管理。 | 不支持、平台限制、系统信息不可读或业务命令失败；具体影响需看各 recipe。 |

菜单的动作编排主要在 `software/menu.py`，通用执行结果在 `software/actions.py`；软件自身安装、路径、服务和配置写入仍由对应 recipe 实现。执行可能需要当前用户具备系统安装、网络或文件权限，权限不足时不能当作成功。

部分软件的“管理”还会进入自己的子菜单：

| 软件 | 子功能及实现位置 | 操作影响和排查 |
| --- | --- | --- |
| WireGuard 服务端 | `wireguard/server.py:manage_peers`：添加、列表、重命名和移除 peer。 | 添加会生成密钥和连接令牌；无服务端状态时修改操作不可用。检查状态、系统权限及实际服务配置，令牌不要写入日志。 |
| WireGuard 客户端 | `wireguard/client.py:manage_client`：查看隧道、更新令牌、删除和添加隧道。 | 已有隧道时才能查看、更新或删除；令牌、网络和配置错误会影响连接。删除和更新会改变本机隧道状态。 |
| Tailscale | `tailscale/server.py:manage_client`：状态、登录、断开和重启。 | 程序未安装时不进入管理；登录依赖认证，断开和重启会影响连接，需要系统权限。 |
| x-ui | `xui/server.py:manage_nodes`：连接信息、状态、服务日志和流量。 | 需要已有业务状态；连接信息可能含敏感数据，日志与流量受服务及系统权限影响。 |
| Oh My Zsh | `software/recipes/ohmyzsh/impl.py:manage_ohmyzsh`：配置 Powerlevel10k、应用预设、切换 shell。 | 依赖当前 shell 和相关程序，可能修改用户配置；切换后需在目标终端验证。 |

RustDesk 提供诊断入口，具体检查范围以[CLI 契约](cli-contract.md)为准；软件专用命令、输出和权限不属于外部插件 SDK。

### 命令行差异

`software list/search/installed/versions` 查询软件；`install/uninstall/upgrade` 不传名称可进入交互选择，传名称时走对应的脚本化参数和能力检查。多版本卸载需要明确版本或全部；安装和升级的版本要求依软件能力而定。`switch`、`diagnose` 接收明确名称，`manage` 是交互入口。具体参数、退出码和已迁移范围见[CLI 契约](cli-contract.md)；菜单选择版本与脚本显式参数不是同一条交互路径。

## 系统监控

菜单入口为 `monitor/menu.py:entry`。概览汇总 CPU、内存、磁盘、网络等状态；详情分别查看 CPU、内存、磁盘、网络接口和进程。实时页面进入采样会话并刷新，返回或中断结束当前页面。采样由 `monitor/commands.py` 和各采样模块完成，读取本机系统与进程信息，不代表插件取得宿主读取权限。

| 子功能 | 处理内容 | 排查重点 |
| --- | --- | --- |
| 概览 / CPU | 获取系统快照、处理器数量、频率和使用率。 | 首样本或采样失败可能没有可用使用率，不能将未知值视为零。 |
| 内存 | 读取物理内存及交换区。 | 不同系统可提供的字段和权限不同。 |
| 磁盘 | 枚举分区并读取容量；采集有独立期限。 | 设备或挂载点卡住、不可访问、worker 失败或超时；空结果不能证明所有挂载均可读。 |
| 网络 | 采样接口累计字节并计算速率。 | 第一次采样缺少前值；接口变化或计数器重置会影响速率。 |
| 进程 | 获取进程信息并显示排行。 | 进程退出、权限不足或 PID 复用；CPU 首样本可能不可用。 |

CLI 的 `monitor dashboard|cpu|memory|disk|network|processes` 提供一次采样或持续采样；进程、网络、磁盘另有各自过滤参数。非 TTY 默认一次；指定采样、过滤或输出选项时不应假设会进入菜单。采样状态、参数互斥、错误和取消退出码详见[CLI 契约](cli-contract.md)。

## 网络工具

菜单入口 `network/menu.py`，业务在 `network/commands.py` 和对应网络模块。下列操作访问本机或网络，受 DNS、目标服务、防火墙、系统命令和网络超时影响；不可达不等于程序已确认远端故障。

| 子功能 | 菜单流程 | CLI 与失败排查 |
| --- | --- | --- |
| Ping | 输入目标，执行并展示收发包及延迟。 | `network ping` 可指定次数和期限；解析失败、目标不可达和进程超时应分开看。 |
| 路由跟踪 | 输入目标，逐行显示路由结果。 | `network traceroute` 可指定跳数与期限；系统工具不可用、超时和目标不响应都会影响结果。 |
| DNS | 选择正向或反向查询，展示地址或名称。 | `network dns` 支持地址族和期限；解析失败或无记录需检查输入与解析服务。 |
| 端口扫描 | 输入目标，扫描常见端口并展示结果。 | `network port-scan` 支持显式端口、并发及期限；当前脚本化扫描为 TCP，超时不等于未扫描端口全部关闭。 |
| 下载测速 | 执行下载并显示速率。 | `network speed-test` 支持 URL 和测量时长；菜单和 CLI 使用不同入口，不能默认测量窗口及输出完全一致。 |
| 内外网 IP | 显示本机及公网地址。 | `network public-ip` 受外部查询服务和期限影响；查询失败不代表本机没有联网。 |

未提供某些目标参数时，CLI 可回到交互入口；非交互环境不能打开菜单。操作取消会尽量终止相关子进程或任务；各命令的期限、结果和具体限制见[CLI 契约](cli-contract.md)。

## 插件工具与外部插件

### 菜单与执行

`plugin/menu.py` 每轮发现可用插件，按清单中的 group 聚合；未分组插件直接显示，分组内选择后运行。进入插件前可能预加载，返回、改选或进入管理时取消不再需要的预加载。发现失败会显示错误；插件执行还要经过清单、启用、信任、运行环境和授权检查。

菜单执行经隔离入口调用插件 `register().entry()`；命令行 `plugin run NAME -- ARGS` 调用插件自己的 `cli(argv)`。插件代码在 worker 中运行，不由宿主直接导入。当前原生插件执行支持 Windows；Linux/macOS 后端未实现时明确拒绝。插件管理菜单可显示不等于当前平台可以执行每个插件。

### 插件管理与维护

| 功能 | 流程和定位 | 风险与失败 |
| --- | --- | --- |
| 安装 | 输入仓库地址与可选分支等信息，采集并校验候选、准备运行环境，再展示来源、权限和内容指纹供用户确认信任。入口 `plugin/menu.py:_install`。 | 来源、认证、网络、清单、依赖准备、磁盘或指纹校验可能失败；菜单拒绝信任会回滚本次安装。CLI 安装与显式指纹授信是分开的步骤。 |
| 更新 | 选择单个或全部，检查已有信任及来源，采集新版本，按结果提示未变化、失败或重新信任。 | 内容变化、降级、来源不可达、正在使用或校验失败需分别处理；更新后的信任和服务授权不可假定沿用。 |
| 卸载 | 选择插件并确认，再移除插件源码及授权。 | 插件正在使用时拒绝；插件持久数据保留，不能把卸载视为清空所有业务数据。 |
| 权限 | 查看、撤销已授予的宿主能力。 | 授权范围绑定插件身份及操作；撤权会影响后续执行和提交。 |
| 维护 | 更新恢复、沙盒配置清理、工作区恢复、缓存清理和磁盘设置。 | 恢复/清理依靠平台记录和身份校验；未知目录不能按名称推定归属并自动删除。 |

安装和更新的认证、信任与恢复细节见[插件规范](plugin-spec.md)和[架构说明](architecture.md)。`plugin/lifecycle_cli.py` 还提供只读检查、显式恢复、准备、启用、禁用和服务授权等命令，完整脚本行为以[CLI 契约](cli-contract.md)为准。

### 插件运行时与宿主边界

插件运行使用独立快照和工作区；通过 SDK 调用的文件、工具、网络和服务请求由宿主验证插件身份、声明、授权、期限和目标。状态提交前还要复核执行、清理和授权条件。失败、撤权或取消时不能仅凭插件函数返回就认定状态已经提交。

目录读取、写入及工具执行是不同的授权范围，既有授权不会自动扩成更高权限；经授权的宿主工具按当前用户权限运行，可能访问项目目录之外。插件自行展示的信息和业务确认不构成宿主授权。跨插件调用需声明服务契约及明确批准调用关系；调用方不能直接共享 Python 对象。接口签名和实际限制见[插件开发指南](plugin-development.md)及[插件规范](plugin-spec.md)。

### Cocos 插件边界

Cocos 在独立 `opskit/plugin/cocos` 仓库，清单声明 Windows 和 SDK 版本 4。用户从“插件工具”进入后，可管理游戏、配置 Creator 和相关工具、构建、查看与清理构建历史、执行 Git 相关业务。其菜单、配置格式、Creator 参数、构建成功判断和保留策略由 Cocos 插件负责；插件使用 SDK 请求文件、工具和产物等受控能力。

框架提供的是通用底层接口，不意味着其他插件现在可以直接调用 Cocos 菜单或共享其状态；当前清单未声明跨插件服务。各业务流程、参数和清理后果以 Cocos 仓库 `README.md` 和 `docs/功能流程与框架边界.md` 为准。Creator 实际构建与真实项目、Git 和远端服务应分别验收。

## 偏好设置

主菜单的偏好设置包含主题和语言。主题列表来自框架主题资源；语言可选中文、英文或自动。选择后调用对应切换函数；取消不选择新值。CLI 可使用 `preferences show`、`theme list/set` 和 `language list/set`，查询及持久化语义见[CLI 契约](cli-contract.md)。面向用户的文案和主题图标规范见[插件开发指南](plugin-development.md)及项目 `AGENTS.md`。
