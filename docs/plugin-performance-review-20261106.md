# 插件系统复审与性能记录（2026-11-06）

本记录对应 `c958d22` 之后的本地修改，覆盖菜单扫描、预加载退出和更新信任失败；它不是整个平台或发布包的验收证明。前一轮清理见[插件系统清理记录](plugin-system-cleanup-20261106.md)。

## 已处理

- 菜单同一轮发现只读取一次启用配置，下轮重新读取；真正执行时仍独立复核启用与信任。运行 `python scripts/benchmark_plugin_listing.py --plugins 50 --runs 7` 可复现配置过滤专项。Windows / Python 3.14.8、隔离配置、50 个合成插件、七次交替热运行：旧方式各次读取配置的中位数 1.1307 秒，当前方式 0.0225 秒。插件发现、目录哈希、信任检查和渲染在该专项中被替身排除；未控制系统缓存及其他负载，不能作为完整菜单的提速比例。
- 普通菜单发现与根菜单的推测性发现共用受控的清单读取进程；后者取消时终止并回收阻塞的读取进程。清单通过有界分块传递，发现阶段不执行插件代码，插件启用、信任和内容仍在实际执行前复核。
- 更新前、更新后及版本回退时的信任确认如果因内容变化等原因失败，会显示错误并返回管理界面；批量更新跳过失败项后继续处理其他插件。用户主动拒绝和校验失败保持不同的界面结果。
- 内容校验及信任指纹目前各自重新读取插件目录。合并读取可减少 I/O，但会缩小对两次检查之间发生修改的检测机会，本轮没有保留该优化。

## 实际菜单观察

在独立数据目录中复制 Cocos 测试插件和固定运行时，按当前 SDK 重新构建独立目录中的运行时记录；没有使用用户的业务状态或项目目录。通过 `scripts/benchmark_plugin_menu_flow.py --root-wait 5 --wait 3 --language zh --expect-label Cocos` 实际进入 Windows 原生沙盒中的插件菜单。记录从选择插件到其子菜单显示，不包括用户在主菜单及插件菜单等待的 8 秒。以下数据采集于统一普通菜单与预加载读取器之前，仅反映当时的中间实现，不代表最终实现的性能。

| 路径 | 秒，逐次样本 | 中位数 |
| --- | --- | --- |
| 当前预加载，首次进程 | 5.723、1.010 | 3.366 |
| 当前预加载，后续进程 | 0.965、0.954、0.961 | 0.961 |
| 修改前根菜单发现，后续进程 | 1.037、2.580、1.217 | 1.217 |
| 禁用预加载 | 5.364、5.476 | 5.420 |

修改前对照使用 `c958d22` 的根菜单发现函数，其余代码是本次工作区版本；不是完整旧版本对照。复用同一机器和测试目录，顺序运行，没有控制操作系统缓存或系统其他负载；两到三次样本不足以估算尾延迟、冷启动或稳定提速。原始输出在忽略目录 `cache/plugin-review-bench-emth79eq/`；测试结束后该目录中的工作区和沙盒配置租约目录为空，未发现命令行包含该测试目录的残留进程。

## 继续审查

- 普通菜单和预加载统一读取器后的完整回归、阻塞取消和真实菜单性能仍需验证；不能将统一之前的测试结果直接视为最终实现的验收结果。
- 当前证据不覆盖正式冻结包、慢磁盘、真实多插件目录、其他机器或首次安装，不能声称已达到性能极限。真实插件和平台仍应分别测试；Windows 是当前唯一原生沙盒后端。
