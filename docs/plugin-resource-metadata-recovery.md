### 未绑定身份记录的恢复设计与验收要求

2026-10-16已实现缺失目标分支：仅当schema3目标仍严格不存在、父目录身份一致，且调用方持实际token租约、恢复worker按platform budget→resource index顺序持锁时，重新核对日志版本及内容并退役该日志。分配worker在同一budget锁内记录意图并mkdir，index锁排除迟到绑定；缺失检查在日志读取前与unlink前各执行一次。存在对象、权限错误、锁忙或身份不确定均保留；普通remove_record仍禁止直接删除schema3。该分支不删除目录，不授予历史未知对象处置权限。

581文件快照的相关回归已完成：Windows342通过4跳过，Linux/macOS各346通过。Windows/Linux独立wheel安装各113项CLI检查及创建前/后的两项真实期限验收通过：创建前意图安全退役，创建后目录、证据及pending记录保留；worker均回收。证据位于忽略目录`cache/absent-intent-source-20261016-r1`。macOS源码测试使用旧cryptography48环境，仅证明该恢复分支回归；锁定cryptography50.0.2的Intel全新安装尚未通过，不能以源码回归替代安全依赖或发布验收。整个维护协议仍未完成。

schema3只证明一次分配尝试，不证明当前同名目录的归属。恢复不得把当前inode补写成“原分配身份”，也不得仅因观察到目录不存在就删除记录：必须先满足上述受锁静止条件，否则迟到worker仍可能创建目录。历史未知目录与损坏日志更不能从名称、年龄或Docker标签反推目录删除权限。

下一步恢复需要两个独立条件：平台能够证明分配活动已经静止；操作者能够明确授权处理当前观察到的具体对象。当前token租约只约束该资源，`platform_state_guard`只覆盖分配/状态预算临界区，均不是已经实现的全平台维护模式。仅获取其中一把锁或查看一次空进程列表，不得声称已排除所有迟到worker。

实施顺序如下，保持未知记录保留策略直至各项验收完成：

1. 明确维护范围为一个规范化平台数据根及对应Docker daemon；新插件调用、分配、状态写入和恢复入口均须参与维护准入协议。定义锁顺序与取消路径，禁止恢复持全局锁等待活动调用，而活动调用又等待该全局锁。
2. 维护独占成功前，既有分配worker必须已退出或被确认回收；父进程死亡、锁句柄继承、worker启动确认丢失及平台重启均纳入协议。停机标记文件、PID字符串和超时等待本身不构成静止证明；旧版本未参与协议的进程必须在离线维护流程中另行排除。
3. 对已绑定schema2记录继续复用既有身份清理。对schema3和历史未知对象，仅生成有界、脱敏的核验结果；明确区分“原归属可证”和“操作者授权处理当前对象”，不伪造归属。普通自动reconcile仍保留不确定项。
4. 如实现人工处置，授权必须绑定数据根/祖先身份、目标当前身份、原记录摘要及具体动作，并在执行点重新核对；路径、父目录、记录或对象变化即拒绝。隔离移动不是无副作用的只读操作，也不是已经释放容量，必须保留预算和可恢复证据。禁止递归删除不受约束的历史内容。
5. 损坏日志先保存有界原始证据和摘要，禁止用猜测的backend/daemon/目录信息重建。不能证明绑定的记录保留为待人工处置，不能算恢复成功。恢复中断及确认丢失必须可重入，不依赖“上次大概已成功”。

最低验收矩阵：

| 场景 | 必须证明的结果 |
|---|---|
| 活动调用、迟到分配worker、新调用竞争 | 未完成静止证明前不改目标；维护期间拒绝或有界等待新准入 |
| schema3创建前/创建后、目录缺失、绑定确认丢失 | 不把观察结果当原归属；普通reconcile继续保留不确定证据 |
| 父目录替换、目标替换、链接/reparse、同名外来目录 | 身份变化拒绝；不越界、不修改外来内容 |
| 满盘、权限拒绝、日志损坏、证据保存失败 | 不先删除原证据，不报告虚假成功 |
| 维护进程取消/死亡、worker父进程死亡、daemon变化 | 释放准入且保留可核验记录；不跨daemon处理资源 |
| Windows/Linux/macOS及安装/冻结入口 | 实际OS锁、实际进程生命周期与退出码验证，不能仅用mock证明 |

本节是后续实现约束，不提供现成的清理命令，也不关闭恢复门槛。新增协议应复用现有监督、身份核对和清理边界；不得为每种失败再叠加一套平行日志/长期双轨实现。

`opskit --output json plugin inspect-workspaces --limit 256` 观察平台 `plugin-runtimes/workspaces` 下的直接条目，limit 为1..256，包含未知条目的整个扫描最多4096项，超限返回失败而非部分成功。命名符合 `opskit-sandbox-` 加32位小写十六进制的条目输出 token 与 kind（directory/unsafe）；其他条目只计入 unknown，不回显名称、路径或内容。directory 仅表示当前观察到普通目录，不表示它属于某租约、没有活动进程或允许删除；unsafe 包括链接、重解析点、普通文件和特殊文件。

检查由受监督 worker 完成，不创建缺失目录、不递归、不读目录内文件、不解析资源日志、不取锁、不调用Docker，也不删除或修改条目。扫描时父目录版本发生变化会拒绝结果，但它仍是有界观察，不能当作与其他命令之间的原子快照。退出0表示观察完成，1表示失败/超限/未确认，2表示参数错误，取消130。缺失目录输出空列表且不初始化应用数据。

此命令补齐身份绑定前孤立工作目录的发现入口，不提供回收权限。当前没有自动清理未知目录的命令；必须保留证据，后续归属修复仍按上节边界处理。它与 inspect-locks 使用不同命名空间，两者的空清单都不能单独证明平台无残留。安装验收器及后续冻结验收器已加入此只读命令；在途578文件构建使用其原19项验收器，不具备新增命令，不能作为本批冻结验收证明。

`opskit --output json plugin inspect-locks --limit 256` 只读检查资源元数据；limit 范围 1..256，按不同 token 计数，目录扫描最多 4096 个条目，超限返回操作失败而非部分成功。目录不存在时返回空清单，不创建运行目录。检查不调用 Docker，不打开日志内容、不获取 token 锁，也不修改文件、权限或索引。

输出 `entries` 中每项包含 token、journal 布尔值与 lock（present/absent/unsafe），另有 unknown 数量。只输出有效 token，不回显未知文件名、路径或日志内容。journal 表示对应路径存在，即使其损坏、是目录或链接也不能作为无日志处理。unsafe 表示锁不是独立普通文件，例如硬链接或链接；unknown 只计数，不能直接作为操作目标。永久 .index.lock 不列出。

这只是有界观察，不是原子快照或无活动证明：`journal=false, lock=present` 的锁可能正由运行进程持有，扫描时也可能发生创建和退役。需要清理时对选定 token 使用下面的 retire-lock，命令将重新取得 index 与实际 OS 锁并复核身份。不要把扫描结果转换成不经复核的批量 unlink。扫描成功退出0，检查失败/超限退出1，参数错误2，取消130；它不修复损坏记录、不枚举 Docker 对象。

## 精确退役

官方维护命令 `opskit plugin retire-lock TOKEN` 按精确 token 退役资源锁元数据，不属于第三方插件业务参数。TOKEN 必须是 32 位小写十六进制，即平台数据目录 `plugin-resources` 中锁文件名去掉 `.lock` 后的部分。命令不接受文件路径，也不扫描或自动猜测未知文件的归属。

使用 `opskit --output json plugin retire-lock TOKEN` 可获得 token 和 `retired`、`absent` 或 `retained` 状态。退出 0 表示锁已退役或已不存在；退出 1 表示保留或操作结果未确认；退出 2 表示输入 token 无效；取消退出 130。结果未确认时可能已执行 unlink，必须检查后再重试，不能当成“没有修改”。

全部路径解析和文件操作在受监督 worker 中执行，复用现有退役实现。worker 持永久 `.index.lock`，确认对应 `.json` 日志不存在、token 锁可独占取得、锁文件和目录身份未变后，关闭 token 句柄并再次核对，然后 unlink。永久 index 不删除。已有日志即使损坏也保留，活动锁、硬链接、链接或身份不确定的元数据不作为成功退役。命令不调用 Docker、不删除资源日志、插件状态或 Docker 对象；有日志的资源先通过 `plugin reconcile` 按原有所有权流程处理。

精确退役解决“已知 token 的历史孤立锁”恢复入口，inspect-locks 补充有界 token 发现；仍不解决未知文件归属、损坏日志修复、未记录 Docker 对象、全局配额和断电持久性。同 UID 恶意宿主竞态及故障网络文件系统的硬期限限制仍存在，不构成额外沙箱保证。
