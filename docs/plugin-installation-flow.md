# 插件安装流程

Windows x64 安装菜单只要求输入仓库地址，并在审核页面决定是否信任插件。首次使用自动准备采集工具和 SDK 运行环境，不需要填写 Python/Git 目录或运行内部准备命令。私网地址、缺少认证或服务器身份无法验证时，按实际问题请求确认或凭据；不会跳过网络和身份检查。

## 顺序

1. 验证输入、目录别名及已有安装冲突。
2. 校验已有采集工具；缺少或策略过期时下载固定版本输入，验证大小、SHA256，安全解压并在 AppContainer 内探测。
3. 使用受限 HTTPS/SSH 获取 Git pack，在隔离 Git 中审核与导出已提交内容。
4. 检查插件清单、SDK 版本、名称冲突和内容凭据。
5. 使用平台固定的 SDK wheel 与哈希锁自动准备运行环境；绑定插件指纹、SDK 摘要与全量文件清单，校验后发布。
6. 原子发布插件目录，初始不授信。
7. 菜单展示名称、版本、类型、权限；用户确认信任后才显示安装成功。拒绝或取消时按照本次目录身份和内容凭据回滚，遇到独立写入者则保留并报告。

命令行 `plugin install` 同样自动准备环境，但继续保留显式 `plugin trust` 的授权模式。服务提供方引导安装复用同一自动准备和确认流程。

## 失败与重试

- 工具准备、仓库传输和运行环境准备分别报告错误，不提前显示“正在克隆”。
- 准备失败不发布插件；已完成且通过校验的输入和工具可供重试复用。
- Ctrl+C 或确认页面取消会退出并执行已有工作区清理；未知目录、被替换的目录及无法验证的记录不会强删。
- SSH 握手前断连属于连接错误，不请求用户填写认证文件；服务器密钥不匹配继续拒绝连接。
- 自动环境包含 SDK 基础依赖。插件额外依赖只能来自审核过的离线输入，不运行仓库 requirements/setup.py 或宿主 pip。
- Linux/macOS 后端仍明确拒绝未实现的原生执行；不降级到宿主 Git/Python。

## 固定输入来源

`core/plugin-bootstrap.json` 随源码、wheel 和 Windows 可执行文件一起发行。Python 摘要来自[官方 Sigstore 文件](https://www.python.org/ftp/python/3.14.10/python-3.14.10-embed-amd64.zip.sigstore)，MinGit 摘要来自[Git for Windows 发行校验表](https://github.com/git-for-windows/git/releases/tag/v2.56.0.windows.4)，SDK wheel 摘要与文件 URL 按各固定版本的 PyPI JSON 核验。运行时不查询 GitHub releases API 或选择 latest。

## 本次验证

- 空数据目录：自动准备工具、隔离采集本地 Cocos 仓库、自动生成并校验运行环境，保持未授信。
- Windows 可执行文件：同样验证首次自动准备和安装；只对自建无业务测试插件显式授信并验证沙盒启动及 SDK/依赖导入。
- 自动准备顺序、失败不发布、取消传播、拒绝信任回滚、目录替换保留、校验失败不写缓存、缓存复用、多语言及发行资源包含已加入测试。
- 真实远程来源 `git.icerror.top` 在 SSH 身份校验前断连，尚未验证该服务器的远程安装成功；不将本地仓库成功代替远端验收。
