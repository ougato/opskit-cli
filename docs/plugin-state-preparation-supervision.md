## 职责和传输

候选准备与只读检查分开：使用现有`network.worker.owned_process`管理一个一次性写入worker。只读ContentInspector不接受写入操作，避免把所有检查的生命周期与候选写入耦合。

宿主在状态锁内检查配额并创建独占`.state-*`目录，将其规范父目录及dev/inode身份绑定到请求。worker只能在该目录下创建`new`；目标插件、caller和最终发布路径不由插件报文指定。准备worker不能取得configuration/trust提交锁、创建事务记录、改名到root或修改旧状态。

现有256KiB检查邮箱不能直接容纳最大32MiB状态文本；普通结果通道也只有64KiB。采用有界共享字节缓冲区传输已验证长度的ASCII base64文本，参数只传缓冲区、实际长度和宿主目录身份。避免通过pipe同步发送大对象，避免反序列化插件提供的pickle。分配、复制和启动均计入同一剩余期限，复制前后复核期限；有限长度并不证明内存分配系统调用可被中断。

worker按原有WIRE_LIMIT、原始归档上限、文件数、内容及元数据预算解码和提取，继续使用受限归档读取与提取器。准备权限在worker内完成；拒绝链接/特殊文件并校验目录身份，返回固定小型JSON结果。成功结果绑定请求随机标识、wrapper身份与新目录身份，宿主拒绝额外字段、类型强转和身份不匹配。错误仅返回固定分类，不传归档成员名称或宿主路径。

## 成功、失败和所有权

成功响应不等于允许发布：父进程先确认准备worker已经退出，再重新核对目录身份，随后持configuration→trust锁复核期限和实时授权，沿用现有事务发布。不得将锁外授权结果缓存成提交许可。

超时、KeyboardInterrupt、父进程死亡或准备失败：先结束并确认worker退出，再考虑清理本次拥有的候选。若无法证明退出，不得在`_state_staging`的finally中递归删除仍可能被写入的目录，应保留并明确报告。父进程崩溃造成的无记录暂存仍占配额，归属恢复须另行设计，不能按名称删除。

本方案不解决发布、事务恢复、递归清理、mkdir以及宿主身份复核的同步I/O问题，也不提供物理空间预留或断电持久性。不得为尽快得到绿色测试而把这些剩余项标记完成。

载荷处理与传输时间、内存均为O(N)，N不超过32MiB文本；同时还存在编码副本、共享缓冲区、解码数据及受限归档元数据。使用有界传输不是低内存或性能提速证明。单次准备使用现有总期限的剩余量，并以30秒控制阶段额度为上限。
