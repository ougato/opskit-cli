## 第三方CLI独立原则

跨插件调用当前各自提交，外层失败不撤销已成功服务调用；历史原生RPC超时根因仍开放，599正常调用链通过也不关闭此门槛。后续选择独立事务加显式持久请求键/回执，意图已确认而结果不明时拒绝自动重试；状态和回执必须同一次可恢复提交，具体实现仍待完成。计时证据、重试限制及幂等/协调提交实施门槛见[RPC事务边界](plugin-rpc-transactions.md)，其中后续协议是计划，不是已有保证。

授权读取已按[当前监督设计](plugin-authorization-supervision.md)迁入独立reader，包含作用域外检查及SDK/网关目录；不能把历史阶段“config/trust仍同步”的结论当作现状。完整manifest及发现/服务目录读取已接入监督。状态事务记录、按目录身份恢复及暂存配额已有实现和三端专项证据；[候选准备监督](plugin-state-preparation-supervision.md)已将解码、提取和权限设置移入受管worker。发布与未记录候选回收已移入worker，513发布批次三端全量已通过；保存前检查及wrapper创建已并入准备worker，状态父目录初始化和sandbox工作目录创建/回收、请求写入与Path转换的三端相关验收已完成；调用锁与资源租约/index/reconcile锁已监督打开和身份复核；日志创建事务已监督，根准备与reconcile扫描也已监督，相关存在性检查与锁元数据退役也已监督，仍需补齐异常文件系统与完整调用链验收；断电持久性、损坏记录修复与未知暂存归属仍开放。状态提交前继续持configuration→trust锁并重新复核，不能复用锁外许可。当前源码验收以链接台账为准，历史快照不能替代本批证明。

平台只注册生命周期及通用路由`plugin run NAME -- ARGS`。ARGS包括help、重复参数和大小写，原样交给插件自身解析；平台不导入第三方业务代码，也不注册第三方业务参数。插件清单只描述身份、入口、权限及接口版本，不能让清单注入宿主命令或管理员shell。

开发者将仓库clone到独立plugins目录；插件源码自身版本控制，平台忽略克隆目录。运行时依赖、状态和缓存不写平台虚拟环境、依赖清单或其他插件目录。升级不自动扩大授权。多租户不可信插件优先采用独立执行节点、gVisor/Kata或微型虚拟机，并验证实际部署威胁模型。

## 仓库提交与垃圾代码标准

源码、SDK、有效测试、配置示例、锁文件及必要文档可以提交。缓存、构建产物、虚拟环境、运行配置、日志、私人编辑器文件、凭据、克隆插件及插件运行数据不提交。当前.gitignore已有这些主要边界，但它不会删除已跟踪文件或历史秘密；检查还要覆盖git跟踪清单、历史及实际构建包。

垃圾代码须有证据：不可达且非公开接口；已完成迁移且兼容期限结束；承担同一语义的重复实现；失效依赖/配置；临时调试入口或误跟踪产物。没有文本引用、低覆盖率、大文件、pass或复杂平台分支，均不能单独作为删除依据。每项先确认动态加载、装饰器注册、SDK、构建、定时器及迁移用途。

opskit-code-health技能已存在于本机Codex技能目录，负责每次相关任务的审查规范，不代表已经配置持续后台扫描。团队约束以本仓文档和CI共同落实。
