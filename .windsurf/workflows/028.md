# 028 - 插件指纹/CHECKSUMS 对换行不敏感，修复 Windows CRLF 误报「内容不符」

## 变更

1. 修复 `core/plugin_integrity.py`：新增 `content_digest(path)`，文本文件先把 CRLF / 单独 CR
   规范化为 LF 再算 sha256（含 NUL 字节的按二进制原样），`_file_hashes` 改用它
2. 修复 `core/plugin_trust.py`：`compute_fingerprint` 改用 `content_digest`，与完整性校验共用同一算法
3. 更新 `.windsurf/plans/001.md` 信任机制章节：注明指纹/CHECKSUMS 用 `content_digest`、对换行不敏感、向后兼容
4. 测试 `tests/test_plugin.py` 新增 `test_checksums_ignore_eol_differences`、`test_fingerprint_ignores_eol_differences`

## 背景

用户在 Windows 上「更新全部」反复出现「Ghost 受控端/客户端/服务端 内容与发布清单 CHECKSUMS.yaml
不符，可能被篡改，已拒绝加载」。根因是完整性校验与信任指纹都对 `f.read_bytes()` 原始字节算
sha256，而 CHECKSUMS 是在 Linux（LF）下生成的；Windows 上 git `autocrlf=true`（Git for
Windows 默认）检出时把文本文件换成 CRLF，字节不同 → sha256 不同 → 误判篡改。在维护机（Linux）
上 `--check` 却通过，正好解释「只在 Windows 复发」。

## 修改方式

- `content_digest`：`data = read_bytes()`；`b"\x00" not in data` 时
  `data.replace(b"\r\n", b"\n").replace(b"\r", b"\n")` 后再 hash。文本规范化、二进制原样。
- 对 LF 内容规范化是空操作，故既有已发布 CHECKSUMS / 已存信任记录无需重算即仍有效（向后兼容）；
  Windows CRLF 检出后归一到 LF 即与清单一致。
- 信任指纹与 CHECKSUMS 完整性校验共用 `content_digest`，两条路径行为一致。
- 防御纵深：三个 Ghost 插件仓（agent-tools / server-tools / client-tools）补 `.gitattributes`
  `* text=auto eol=lf`，保证在任意平台 checkout 为 LF，即使旧版 opskit（未含本修复）也不再误报。

## 测试

- `.venv/bin/python -m pytest tests/test_plugin.py`：38 passed（新增 2 项换行不敏感回归）。
